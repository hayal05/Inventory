## Summary
Light, simple inventory management for pharmacies, retailers, and wholesalers. Built on a free-tier stack with a stock ledger, optional batch/expiry tracking (FEFO), and a dark dashboard UI based on the supplied reference.

## Stack
| Layer | Choice |
|---|---|
| Backend | Node.js + Express |
| Frontend | React (Vite) PWA |
| Database | Neon Postgres (pooled connection, Drizzle ORM) |
| Images | Cloudinary (direct browser upload, signed by backend) |
| Hosting | Render free tier (single service) |
| Keep-alive | Uptime bot pinging DB-free `/health` |

## Key decisions
- Stock is a ledger (`stock_movements`); quantity is never edited directly.
- Multi-tenant: `org_id` on every table and every query.
- Batches and expiry are optional per product (`track_batches`).
- Issue stock uses FEFO (earliest expiry first).
- Images are stored in Cloudinary; only the URL and public ID are in the DB.
- `/health` never touches the DB, so Neon can sleep when idle.
- UI follows the dark navy reference with cyan and magenta accents.

## Risks and notes
- Replacing or clearing a product image, or soft-deleting a product, leaves the old file in Cloudinary (deleting needs a signed server-side call). Harmless at small scale; revisit if the free storage fills up.
- Changing `track_batches` on a product that already has stock is allowed by `PUT` today. Once the ledger exists (tasks 24-30), decide whether to block that change when the product has movements.
- Sessions are stateless JWTs (7 days), so a deactivated user keeps access until the token expires. If that is not acceptable, make `requireAuth` check `users.is_active` in the DB on each request.
- Neon cold starts add a short delay after idle; the UI needs a loading message and the server a connect retry.
- Neon free storage is 0.5 GB; keep images out of the DB.
- Render free filesystem is ephemeral; never write uploads to disk.
- Free-tier backups are limited; weekly `pg_dump` via GitHub Action is planned (task 68).
