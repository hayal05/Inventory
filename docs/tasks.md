# Inventory Management System: Build Tasks

**Stack:** Node.js (Express) + React (Vite) + Neon Postgres + Cloudinary, deployed as one Render service, kept awake by an uptime bot.

**How to use:** Do the tasks in order, tick each box when its "done" check passes, and commit after every task. Each task is about 15-45 minutes.

**UI direction (from reference):** dark navy background, cyan and magenta accents, green/red trend badges, left sidebar with search, 4 KPI cards, a large area chart, and two small side panels.

**Inventory mapping:** KPI cards are Total products, Stock value, Low stock, and Expiring soon. The big chart shows stock received vs sold per month. Side panels show movements per day and an expiring-batches list.

## Phase 4: Stock ledger
- [x] 24. Write a helper `addMovement()` that inserts a ledger row inside a transaction. *`addMovement(tx, input)` in `server/src/lib/ledger.js`; the caller passes a transaction (`db.transaction(async (tx) => ...)`). Locks the product row, checks org ownership, batch rules, sign per type, and rejects with 409 `INSUFFICIENT_STOCK` if stock would go below zero.*
- [x] 25. `POST /stock/receive`, with optional batch number and expiry. *At `POST /api/stock/receive` (staff+). Body: `productId`, `qty`, optional `locationId` (defaults to the org's first location), `unitCost`, `batchNo`, `expiryDate` (YYYY-MM-DD), `note`. A `track_batches` product requires `batchNo` and `expiryDate`; the batch is created on first receipt and reused after (409 if the same batch number is sent with a different expiry). Other products must not send them. Returns 201 `{ movement, batch }`.*
- [x] 26. `POST /stock/adjust` with a required reason. *At `POST /api/stock/adjust` (staff+). Body: `productId`, signed `qtyDelta` (+ adds, - removes), `reason`, optional `locationId` (defaults to first location), `batchId` (required for `track_batches` products), `note`. Returns 201 `{ movement }`; 409 `INSUFFICIENT_STOCK` if stock would go below zero.*
- [x] 27. `GET /stock` returns current levels per product and location, using SUM. *At `GET /api/stock?q=&productId=&locationId=&includeZero=&includeBatches=&page=&limit=` (all roles). Rows with 0 stock are hidden unless `includeZero=true`; `includeBatches=true` adds a FEFO-ordered `batches` list to each row. Returns `{ items, page, limit, total, totalPages }`.*
- [x] 28. `GET /products/:id/movements` returns the history. *At `GET /api/products/:id/movements?type=&locationId=&page=&limit=` (all roles), newest first. Each row has `type`, `qtyDelta`, `location`, `batch` (or null), `unitCost`, `reason`, `note`, `user` (email), `createdAt`. 404 for unknown, other-org, malformed-id, or soft-deleted products.*
- [x] 29. FEFO picker: given a product and a qty, return batches to draw from, earliest expiry first. *`pickFefo(tx, { orgId, productId, locationId, qty, today? })` in `server/src/lib/fefo.js`, with the pure allocation in `lib/fefoPlan.js`. Skips expired batches (a batch is usable through its expiry date), uses batches with no expiry last, and returns `{ picks, shortfall, available, expiredQty }` instead of throwing on a shortfall. A helper, not an endpoint; task 30 uses it.*
- [x] 30. `POST /stock/issue` uses the FEFO picker and rejects the request if stock would go negative. *At `POST /api/stock/issue` (staff+). Body: `productId`, positive `qty`, optional `locationId` (defaults to first location), `note`. Batch-tracked products are drawn FEFO, one ledger row per batch, all in one transaction. Returns 201 `{ movements, picks }`; 409 `INSUFFICIENT_STOCK` (message says if expired stock was left out); 404 for unknown product or location.*

## Phase 5: Reports
- [x] 31. `GET /reports/low-stock`, for products at or below their reorder level. *At `GET /api/reports/low-stock?page=&limit=` (all roles). Uses total on hand across all locations; products with reorder level 0 (not set) are not flagged. Most short first. Each item: `productId`, `sku`, `name`, `category`, `baseUnit`, `reorderLevel`, `onHand`, `shortfall`. Also wires `GET /api/products?lowStock=true` (same rule).*
- [x] 32. `GET /reports/expiring?days=90`. *At `GET /api/reports/expiring?days=&page=&limit=` (all roles; `days` 1-365, default 90). Lists batches that still have stock and expire within the window, plus batches already expired but still on hand. One row per batch and location, soonest first. Each item: `productId`, `sku`, `name`, `baseUnit`, `batchId`, `batchNo`, `expiryDate`, `locationId`, `locationName`, `qty`, `daysLeft` (negative = expired), `expired`. Response also has `asOf` and `days`. Uses the UTC date, like FEFO.*
- [x] 33. `GET /reports/valuation`. *At `GET /api/reports/valuation?page=&limit=` (all roles). Value = total on hand (all locations) x product `cost_price`, for active products with stock, biggest first. Products with no cost price have `value: null` and are counted in `totals.productsMissingCost`. Returns `totals { totalValue, totalUnits, productsWithStock, productsMissingCost }` plus paginated `items` (`productId`, `sku`, `name`, `category`, `baseUnit`, `costPrice`, `onHand`, `value`). Money is exact strings with 2 decimals.*
- [x] 34. `GET /dashboard/summary` returns the 4 KPI numbers plus their % change. *At `GET /api/dashboard/summary?compareDays=30&expiringDays=30` (all roles; both 1-365). Returns `kpis.totalProducts`, `kpis.stockValue` (exact string, plus `missingCost`), `kpis.lowStock`, `kpis.expiringSoon`, each `{ value, previous, changePct }`. `previous` is the same figure `compareDays` days ago, rebuilt from the ledger; `changePct` has 1 decimal and is `null` when the previous value was 0 and the value is not.*
- [x] 35. `GET /dashboard/monthly` returns received vs issued per month, for the chart. *At `GET /api/dashboard/monthly?months=12` (all roles; `months` 1-24). Returns `{ asOf, months, items: [{ month: 'YYYY-MM', received, issued }] }`, oldest first, ending with the current UTC month. Every month is present (0 and 0 when nothing moved). Counts only `receive` and `issue` rows (`issued` is positive); adjustments, returns and expiry write-offs are left out.*
